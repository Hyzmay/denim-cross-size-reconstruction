# 牛仔裤跨尺码重构项目完整理解 - 教师提问版

更新时间：2026-09-06

## 这份文档怎么用

不要从代码第一行开始背。按下面顺序学习：

1. 先说清楚系统解决什么问题。
2. 再说清楚尺码表如何变成几何比例。
3. 再跟踪一张图片经过每个模块后发生了什么。
4. 最后判断每个输出能证明什么、不能证明什么。

## 第一课：项目真正解决什么问题

### 老师提问 1

这个项目是不是把一张牛仔裤图片整体放大或缩小？

### 标准回答

不是。整体 resize 会让腰、臀、裆、裤腿和裤长使用同一个比例，也会同步拉伸口袋、缝线、洗水和织纹。真实服装放码不是这种变化。

目标问题是：

```text
单张牛仔裤图片 + 源尺码 + 目标尺码
    -> 目标尺码牛仔裤图片
```

内部希望完成：

```text
分割
-> 结构理解
-> canonical 表示
-> 尺码几何比例
-> 局部变形
-> 新区域检测
-> 原图纹理补全
-> 边缘修复
-> 输出与评估
```

最高原则是：能保留的真实像素尽量保留；确实需要变形的部分才变形；确实新增的区域才补纹理。

### 老师提问 2

为什么最终用户不需要 DXF？

### 标准回答

因为产品目标是“图片 + 目标尺码”。DXF 应当在研发阶段提供真实纸样轮廓、物理尺寸和结构点，用于监督和评估，而不是成为用户每次运行的必需输入。

### 当前实现和最终目标的区别

当前版本是 Phase 0/1 经典视觉 baseline。它能在干净白底商品图上跑通全部流程，但还没有从单图恢复工业纸样，也没有用 DXF 验证物理厘米误差。

## 第二课：先理解输入、输出和坐标

### 老师提问

系统最少需要知道什么？

### 标准回答

当前代码实际需要：

```text
source_image
source_size
target_size 或 target_sizes
size_profile
```

例如：

```powershell
.\.venv\Scripts\python.exe -m denim_resize "data\photo\1.jpg" `
  --output "runs\lesson" `
  --source-size 34 `
  --target-sizes 32,33,34,36,38
```

命令入口是 [`denim_resize/__main__.py`](../../denim_resize/__main__.py)。单尺码执行 `run_reconstruction()`，多个尺码执行 `run_size_series()`，总调度位于 [`denim_resize/run.py`](../../denim_resize/run.py)。

### 必须区分的四种坐标

1. 原始图像坐标：整张输入图的像素位置。
2. 裤装裁剪坐标：裤子 bounding box 内的像素位置。
3. Canonical 坐标：把不同裤型归一化到 `u in [-1,1]`、`v in [0,1]`。
4. 输出坐标：目标尺码画布中的像素位置。

当前版本没有 DXF/model 坐标和厘米到像素的绝对标定，只使用尺码之间的相对比例。

## 第三课：尺码表怎样控制变形

### 老师提问 1

现在的尺码数据是不是写死的？

### 标准回答

是。当前只有一个商品专属尺码表写在 [`denim_resize/sizes.py`](../../denim_resize/sizes.py) 中，默认 profile 是 `taobao_612962220220`，包含 `32/33/34/36/38`。

但是变形结果不是写死的。程序根据源尺码和目标尺码实时计算比例：

```text
r_waist = target_waist / source_waist
r_hip = target_hip / source_hip
r_knee = target_knee / source_knee
r_length = target_outseam / source_outseam
r_rise = target_front_rise / source_front_rise
```

比例计算在 [`DeformationRatios.from_measurements()`](../../denim_resize/deformation.py)。

### 老师提问 2

你刚提供的 S-3XL 表能直接替换吗？

### 标准回答

可以成为新的商品 profile，但不能无条件塞进旧字段。新表包含：

| 尺码 | 裤长 | 平铺腰宽 | 坐围/臀围 | 脚口 |
|---|---:|---:|---:|---:|
| S | 102 | 33.5 | 96 | 37.0 |
| M | 103 | 35.5 | 100 | 37.6 |
| L | 104 | 37.5 | 104 | 38.3 |
| XL | 105 | 39.5 | 108 | 38.9 |
| 2XL | 106 | 41.5 | 112 | 39.5 |
| 3XL | 107 | 43.5 | 116 | 40.2 |

它缺少膝围、前浪和后浪。正确做法是保留“缺失”状态，并用明确记录的规则估计膝部和裆部变化，不能把估计值伪装成商家实测值。

### 重要判断

`runs/1` 的配置仍显示 `taobao_612962220220` 和 `34 -> 32/33/34/36/38`，所以它不是基于新 S-3XL 表生成的真实结果。

## 第四课：Garment Segmentation

代码：[`denim_resize/segmentation.py`](../../denim_resize/segmentation.py)

### 老师提问

第一步为什么必须得到裤子 mask？

### 标准回答

几何变形只能作用于裤子。如果背景被当成裤子，背景颜色会进入纹理；如果裤脚或腰带被漏掉，后面所有结构点和尺寸都会错误。

### 当前算法

1. 把 BGR 图像转换到 Lab 色彩空间。
2. 从图像四周估计背景颜色中位数。
3. 用 robust MAD 距离阈值区分前景和背景。
4. 用形态学开闭运算清理噪声。
5. 可选 GrabCut 细化。
6. 只保留面积接近主物体的一个或两个连通域。
7. 检查前景面积比例是否合理。

### 输入与输出

```text
输入：BGR uint8 图片
输出：bool pants mask + diagnostics
```

主要产物：`pants_mask.png`、`foreground.png`、`overlay.png`。

### 当前局限

它依赖“边缘大多是背景”的假设。白底商品图较合适；人体穿着、复杂背景、阴影、水印和裤子接触图像边界时容易失败。它不是语义分割神经网络。

### 自检题

如果 mask 把两条裤腿之间的空隙填满，会发生什么？

答案：裆点会被推到错误位置，后续 canonical 和裤腿变形都会错。

## 第五课：Garment Structure Understanding

代码：[`denim_resize/structure.py`](../../denim_resize/structure.py)

### 老师提问

有了二值 mask，为什么还不够？

### 标准回答

Mask 只告诉系统“哪里是裤子”，不知道哪里是腰、臀、裆、膝和裤脚。跨尺码变化必须在这些结构层之间分配。

### 当前算法

- `row_runs()` 找每一行的连续前景区间。
- `_detect_crotch()` 从上到下寻找由一个区间稳定分裂成两个区间的位置。
- 臀部位置目前用 `crotch * 0.52` 估计。
- 膝部位置目前用裆点到裤脚距离的 `0.52` 估计。
- 顶端和底端分别作为腰线和裤脚线。

### 关键事实

臀部和膝部仍是启发式位置，不是模型识别，也没有人工 landmark 或 DXF 验证。

主要产物：`structure_landmarks.png`。

## 第六课：Canonical Garment Representation

代码：[`denim_resize/canonical.py`](../../denim_resize/canonical.py)

### 老师提问 1

Canonical 表示解决什么问题？

### 标准回答

它给不同图片里的裤子建立共同坐标。即使裤子像素尺寸不同，“腰带、左臀、右臀、裆、左右大腿、左右膝腿、左右裤脚”仍可以用相同区域名称和归一化坐标描述。

### 当前表示

- 横向 `u`：左边约为 `-1`，中间约为 `0`，右边约为 `1`。
- 纵向 `v`：腰为 `0`，臀为 `0.22`，裆为 `0.40`，膝为 `0.68`，裤脚为 `1.0`。
- 语义区域：10 个裤装区域。

主要产物：`canonical_uv.png`、`semantic_regions.png`、`canonical_representation.npz`。

### 老师提问 2

现在的 canonical 是否真的控制了变形？

### 标准回答

没有。当前 `run.py` 会构建并保存 canonical，但 `warp_component()` 没有接收 canonical UV 或 regions。它目前是诊断表示，不是变形的控制变量。

这是理解当前版本最重要的事实之一。

## 第七课：Target-size Geometry 与局部变形

代码：[`denim_resize/deformation.py`](../../denim_resize/deformation.py)

### 老师提问

当前“局部变形”具体是什么意思？

### 标准回答

当前不是神经网络 local flow，也不是三角网格。它按裤子的纵向位置，在腰、臀、裆、膝、裤脚几个 anchor 之间线性插值横向比例。

横向 anchor 大致为：

```text
腰 -> r_waist
臀 -> r_hip
裆 -> r_hip
膝 -> r_knee
裤脚 -> r_knee
```

每个目标行先映射回源图行，再把该行的一个或两个裤装区间按当前横向比例映射到目标画布。OpenCV `remap` 使用三次插值采样源像素。

裤长由 `r_length` 决定，目标裆深由 `r_rise` 决定。

### 当前局限

- 裤脚仍沿用膝围比例，没有独立 hem ratio。
- Canonical 10 区没有真正参与 warp。
- 没有 mesh foldover、Jacobian 或 seam-length 约束。
- 口袋和缝线会随所在行一起变形。
- “一个连通域一个 component”不等于“十个语义区域十个 local flow”。

主要产物：`reconstructed_baseline.png`、`target_mask.png`、`displacement_field.png`、`local_scale_map.png`。

## 第八课：Original Detail Preservation

代码：[`denim_resize/details.py`](../../denim_resize/details.py)

### 老师提问

系统怎样发现缝线、口袋边和强纹理？

### 标准回答

当前算法对灰度图做高斯平滑和 Sobel 梯度，取裤装内部梯度强度的第 88 百分位作为阈值，保留足够大的强边缘连通域，并把轮廓边缘一起放入 protected mask。

主要产物：`detail_constraints.png`、`detail_protection_mask.png`。

### 必须避免的误解

当前细节保护发生在几何 warp 之后，protected mask 只阻止纹理补全覆盖这些区域。它不能阻止前面的 remap 拉伸口袋、缝线或印花。

真正的 detail-aware warping 仍是后续工作。

## 第九课：New-region Detection 与真实纹理补全

代码：[`denim_resize/completion.py`](../../denim_resize/completion.py)

### 老师提问 1

什么叫“新增区域”？

### 标准回答

当前实现把目标 mask 与单位比例下可保留区域作差：

```text
new_region = target_mask AND NOT preserved_mask
```

这是一个几何代理定义，表示扩码后落在原宽度之外的区域。它不等同于真实布料制造或三维可见性分析。

### 老师提问 2

补纹理是不是生成一条新裤子？

### 标准回答

不是。它只从同一输入裤子的有效内部区域寻找 donor patch，不使用扩散模型或 GAN。

当前步骤：

1. 从 new region 中排除 protected mask。
2. 从非新增、非保护的内部区域选择 donor patches。
3. 将图像分为低频 base 和高频 residual。
4. 用 Lab 均值、局部方差、梯度和位置组成 patch 特征。
5. 用 KD-tree 找最近 donor。
6. 将连续镜像 residual 与 patch vote 混合。
7. 搜索纹理注入强度。
8. 如果纹理梯度差没有改善，就保留 warp baseline。

### Acceptance gate

- 可补区域覆盖率至少 95%。
- 补全后的 gradient-energy gap 不得大于补全前。
- donor 和 mask 外像素不能改变。

`completion_applied=false` 不表示失败，而表示候选没有优于 baseline，所以系统拒绝强行修改。

主要产物：`new_region_mask.png`、`texture_completion_regions.png`、`texture_completion_comparison.png`。

## 第十课：边缘为什么曾经出现白边

代码：[`denim_resize/matting.py`](../../denim_resize/matting.py)、[`denim_resize/edge.py`](../../denim_resize/edge.py)

### 老师提问

白边是怎么产生的？

### 标准回答

插值器在裤装轮廓附近同时读到深色牛仔像素和白色背景，混合后形成灰白边或锯齿。

### 当前修复

1. 在源图上建立 trimap，用背景颜色、最近内部前景颜色和颜色投影估计 source alpha。
2. 对半透明边缘做前景颜色去污染，避免把白底混色当成牛仔像素。
3. 前景颜色和 alpha 使用同一个 remap 一起变形。
4. 用距离变换把最近的前景颜色延拓到目标 mask 外。
5. 小范围开闭运算和高斯平滑目标轮廓，并与 warped alpha 合并。
6. 检查轮廓面积漂移，超过 1.5% 就回退。
7. 用最终 alpha 与白底合成，并检查轮廓粗糙度不能增加。

主要产物：`source_alpha.png`、`source_foreground_matte.png`、`edge_alpha.png`、`refined_target_mask.png`、`edge_refinement_comparison.png`。

注意：这一步改善的是显示边界，不证明目标裤型物理正确。

当源尺码等于目标尺码时，系统还记录 identity gate：mask IoU、boundary F1、内部像素 MAE 和 alpha MAE。它用于证明边缘处理没有破坏原图，不用于证明跨尺码结果正确。

## 第十一课：评估、测试和可复现性

代码：[`denim_resize/metrics.py`](../../denim_resize/metrics.py)、[`tests/`](../../tests/)

### 老师提问 1

`all_sizes_accepted=true` 能否证明换码完全正确？

### 标准回答

不能。它只表示当前 texture gate 和 edge gate 通过。没有 DXF、目标尺码实物图或人工结构标注时，不能计算真实厘米误差和目标轮廓误差。

### 当前有的指标

- 分割：IoU、Dice、boundary F1，需要人工 GT mask 才有意义。
- 结构：结构点顺序和基本几何合理性。
- Canonical：mask coverage 和区域数量。
- 纹理：new-region coverage、gradient gap、interface MAE。
- 边缘：面积变化、粗糙度和亚像素过渡像素。
- 可复现：输入 SHA-256、参数、随机种子、依赖版本和 Git revision。

### 当前缺失的核心指标

- 与目标尺码 DXF 的 contour distance。
- 腰、臀、膝、裤脚和裤长的厘米误差。
- landmark reprojection error。
- mesh foldover/Jacobian distortion。
- 缝线连续性、口袋形状和织纹方向误差。
- 同款真实目标尺码照片的配对比较。

## 第十二课：一张图在代码中的完整旅程

总调度位于 `run_reconstruction()`：

```text
read_bgr
  -> segment_pants
  -> infer_pants_structures
  -> build_canonical_garment
  -> get_size_profile + DeformationRatios
  -> warp_component
  -> compose_components
  -> detect_detail_constraints
  -> complete_texture_exemplar
  -> refine_garment_edge
  -> write images/json/npz
```

多尺码 `run_size_series()` 对每个目标尺码重复上面的完整流程，再把结果按相同像素比例拼成 `size_series.png`。

### 模块责任表

| 文件 | 责任 | 不能把它误认为 |
|---|---|---|
| `io.py` | 读写图片、mask、SHA-256 | 图像算法 |
| `segmentation.py` | 白底/边缘背景先验分割 | 通用服装解析模型 |
| `matting.py` | 源 alpha 估计和边缘颜色去污染 | 精确人工 alpha 标注 |
| `structure.py` | 启发式腰臀裆膝裤脚位置 | 精确 landmark 模型 |
| `canonical.py` | 归一化 UV 和 10 区诊断 | 已参与 warp 的 canonical 网络 |
| `sizes.py` | 商品尺码表注册表 | 通用淘宝尺码标准 |
| `deformation.py` | 逐行比例插值和 remap | GP-VTON local flow 或 TPS mesh |
| `details.py` | 强梯度和轮廓保护 mask | 缝线/口袋语义识别器 |
| `completion.py` | 同图 exemplar residual 补纹理 | 生成式服装模型 |
| `edge.py` | 颜色延拓、轮廓平滑、alpha | 几何正确性模块 |
| `metrics.py` | mask 和代理质量指标 | 物理尺码验证 |
| `visualization.py` | 拼图和诊断可视化 | 变形算法 |
| `run.py` | 串联、保存和记录 | 单个核心模型 |

## 第十三课：怎样读一次运行结果

先按以下顺序看，而不是只看 `reconstructed.png`：

1. `source_mask.png`：裤子是否完整，背景是否混入。
2. `source_alpha.png`、`source_foreground_matte.png`：亚像素边界和白底污染是否合理移除。
3. `structure_landmarks.png`：腰、臀、裆、膝、裤脚是否合理。
4. `semantic_regions.png`：10 区是否覆盖正确。
5. `local_scale_map.png`：哪里扩得多、哪里扩得少。
6. `new_region_mask.png`：系统认为新增布料在哪里。
7. `detail_protection_mask.png`：哪些细节禁止被补纹理覆盖。
8. `texture_completion_comparison.png`：补纹理是否真的优于 baseline。
9. `edge_refinement_comparison.png`：白边和锯齿是否改善。
10. `metrics.json`：代理 gate 是否通过，identity gate 是否适用，以及 `physical_geometry_evaluated` 是否为真。
11. `config.json`：到底使用了哪个尺码表和哪些比例。

## 第十四课：优化顺序

优化不能先从“让图片更漂亮”开始。推荐顺序：

1. 先让源图 segmentation、alpha matting 和同尺码 identity gate 稳定通过。
2. 把你提供的 S-3XL 商品表变成独立、可替换的 profile，并增加独立脚口比例。
3. 明确原图真实源尺码，重新生成正确结果。
4. 建立人工 mask 与腰/臀/裆/膝/裤脚 landmarks。
5. 让 canonical regions 真正参与 deformation。
6. 将逐行插值升级为受边界和内部结构约束的 mesh/TPS deformation。
6. 在 warp 前检测并约束口袋、门襟、侧缝和内缝。
7. 用真实同款跨尺码照片或 DXF 验证物理几何。
8. 最后优化新增区域纹理方向、重复 patch 和色落连续性。
